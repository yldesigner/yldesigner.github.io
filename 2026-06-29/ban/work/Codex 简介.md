# Codex 简介

> [!summary] 一句话介绍
> **Codex 是 OpenAI 面向软件开发的 AI 编程智能体**。它不仅能回答代码问题，还能读取项目、修改文件、运行命令与测试，并把结果交给人审阅。

## Codex 能做什么

- **编写代码**：根据需求开发功能、生成脚手架，并遵循现有项目的结构和约定。
- **理解代码库**：梳理陌生或遗留项目，解释模块关系、数据流和关键实现。
- **审查代码**：检查潜在缺陷、逻辑错误、遗漏的边界情况和测试不足。
- **调试与修复**：复现问题、定位根因、实施修复并运行验证。
- **自动化工程任务**：处理重构、迁移、测试、文档和重复性维护工作。

## 在哪里使用

Codex 可以通过多个入口工作，并使用同一个 ChatGPT 账户连接：

| 入口 | 适合的场景 |
| --- | --- |
| Codex App | 管理多个项目与线程、查看改动、运行并行或后台任务 |
| IDE 扩展 | 在编辑器中围绕当前文件和选中代码协作 |
| Codex CLI | 在终端中直接读取仓库、编辑文件和运行命令 |
| Codex Web / Cloud | 把任务委托给隔离的云端环境执行 |

Codex 还可以通过 **Skills** 固化可复用流程，通过 **Automations** 定时执行例行任务，并借助 **MCP、插件或连接器**接入外部工具和数据。

## 它和普通聊天助手有什么不同

普通聊天助手通常给出建议或代码片段；Codex 更像一位可以在受控环境里动手工作的协作者：

1. 读取仓库和项目说明。
2. 制定或确认实现路径。
3. 修改真实文件并运行工具。
4. 执行测试、检查结果。
5. 汇报变更、风险与未解决问题，等待人工审阅。

因此，Codex 的价值不只是“生成代码”，而是把理解、修改、验证和交付串成一个可检查的工程闭环。

## 怎样给 Codex 一个好任务

一个高质量任务通常包含四部分：

- **目标**：最终要实现什么。
- **范围**：允许修改哪些目录、组件或文件。
- **约束**：技术栈、兼容性、风格、安全或性能要求。
- **验收标准**：需要通过哪些测试，或怎样判断任务完成。

示例：

```text
为登录接口增加基于 IP 的速率限制，只修改后端认证模块。
沿用现有 Redis 客户端，不引入新依赖；补充单元测试，最后运行认证模块测试并说明结果。
```

如果是复杂任务，可以先让 Codex 调研并提出计划，再授权它实施；如果是范围明确的小改动，可以直接要求它修改并验证。

## 安全与使用边界

- Codex 会受到工作目录、沙箱、网络访问和审批策略的限制；高权限操作可能需要用户确认。
- AI 生成的代码仍可能存在错误。合并或部署前，应检查 diff、测试结果、安全影响和数据迁移方案。
- 不要把密钥、令牌或生产数据直接写进提示词、源码或日志。
- 对付款、权限、删除数据、生产发布等高影响操作，应保留人工审批和回滚方案。

## 适合与不适合的任务

**特别适合：**目标明确的功能开发、Bug 修复、代码解释、测试补充、重构、迁移、代码审查和文档整理。

**需要更多人工主导：**需求尚未形成共识的产品决策、无法验证的开放式任务，以及涉及生产数据或不可逆操作的高风险变更。
